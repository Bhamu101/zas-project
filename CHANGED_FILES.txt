## 2026-08-27 — Per-crop moisture targets + bed crop labels + gradual irrigation sim

- backend/main.py — added a per-crop CROP_TARGETS table (Covo: trigger 32 /
  optimal 48-68%, Tsunga: 30 / 45-65%, Tomato: 22 / 34-52% VWC — leafy brassicas

  Re-seeded Bed 2 (38%) and Bed 3 (44%) so their states still line up with the new

  thresholds; the manual-trigger and stop-irrigation endpoints use it instead of a
  hardcoded ">= 40".

  backend) + bedTargets(bed, systemInfo) which resolves a bed's thresholds, preferring
  per-bed backend values, then the per-crop table, then system-wide defaults. Also
  returns the resolved crop name, so it doubles as the crop-label fallback.
- irrigation-dashboard/src/pages/BedMonitoring.jsx — bed card heading reads "Bed N:
  Crop" as plain text at text-xl (no icon/chip). Range bar, the "<crop> optimal:
  X-Y% / trigger < Z%" line, the Recommended-Actions text (now quotes the real band /
  trigger numbers), and the Moisture Trend legend all use bedTargets() — so each bed
  shows its own crop's range. Moisture Trend now draws one faint shaded band per
  crop's optimal range instead of a single system-wide band.
- irrigation-dashboard/src/pages/IrrigationControl.jsx — bed card heading "Bed N:
  Crop" plain text at text-lg; the target line shows "<crop> target: X-Y% · trigger
  < Z%" per bed. "Trigger Irrigation Now" no longer POSTs to the backend (which
  jumped VWC +22 instantly) — it runs a client-side sim: the reading climbs gradually
  (~1.4%/tick w/ jitter every 450ms) toward the middle of that crop's optimal band,
  the % counts up live, droplet icon pulses, status badge re-derives against the
  crop's own thresholds, progress bar fills, button shows "Irrigating… NN%" disabled,
  and the Bed Moisture Map node tracks it. Intervals cleared on unmount / re-trigger.
  Removed the dead fetch/error-banner code, the unused onIrrigationTriggered prop and
